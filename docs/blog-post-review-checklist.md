# Blog Post Review Checklist

Use this checklist to review and approve generated blog posts before publishing.

## Pre-Review: Content Assessment

### 1. Meaningfulness
- [ ] Does this post contain substantive information?
- [ ] Is the content unique (not a duplicate of a previous post)?
- [ ] Does this provide value to readers?
- [ ] Is the note substantive enough to warrant a post?

### 2. Relevance
- [ ] Is this relevant to the repository's purpose?
- [ ] Does it address a real problem or learning opportunity?
- [ ] Is the content timely and current?
- [ ] Would a reader find this useful?

### 3. Uniqueness Check
- [ ] Is this post unique (not a duplicate of another post)?
- [ ] Does it add new information or perspective?
- [ ] Is the note different enough from previous posts?

## Structural Review

### 4. Title Quality
- [ ] Title is clear and descriptive
- [ ] Title reflects actual content (not just "Run X: error")
- [ ] Title uses action-oriented language
- [ ] Title is not overly generic

### 5. Content Structure
- [ ] Has clear sections (Context, Attempt, Result, Lesson)
- [ ] Uses appropriate subheadings
- [ ] Has logical flow
- [ ] Paragraphs are concise (2-4 sentences)

### 6. Formatting
- [ ] Uses proper Markdown syntax
- [ ] Includes Jekyll frontmatter
- [ ] Code snippets are properly formatted
- [ ] Tables are properly formatted
- [ ] Links work correctly

## Quality Standards

### 7. Readability
- [ ] Easy to scan and read
- [ ] Uses bullet points where appropriate
- [ ] Has clear headings and subheadings
- [ ] Avoids overly long paragraphs

### 8. Accuracy
- [ ] Technical details are correct
- [ ] Dates and numbers are accurate
- [ ] Code examples work
- [ ] Links are valid

### 9. Tone and Style
- [ ] Tone is professional
- [ ] Language is accessible to general technical audience
- [ ] Explains technical concepts when needed
- [ ] Uses plain language where possible

### 10. Clarity
- [ ] Ideas are clearly expressed
- [ ] Avoids unnecessary jargon
- [ ] Uses examples to illustrate points
- [ ] Is concise and to the point

## Specific Content Review

### 11. Context
- [ ] Explains what was being worked on
- [ ] Provides necessary background
- [ ] Sets the scene for readers

### 12. Attempt
- [ ] Describes what was tried
- [ ] Includes technical details
- [ ] Shows the approach taken

### 13. Result
- [ ] Explains what happened
- [ ] Includes outcomes (success or failure)
- [ ] Provides specific results

### 14. Lesson Learned
- [ ] Identifies key takeaways
- [ ] Explains how to apply the learning
- [ ] Provides actionable insights
- [ ] Frames failure as learning opportunity

## Post-Generation Validation

### 15. Technical Validation
- [ ] Check site builds successfully
- [ ] No broken links in post
- [ ] No syntax errors in Markdown
- [ ] Image paths are correct (if any)
- [ ] Tables render correctly

### 16. Cross-Reference Check
- [ ] Links to other posts work
- [ ] Links to documentation work
- [ ] Internal references are correct
- [ ] External links are valid

### 17. Reviewer Approval
- [ ] Reviewed by human editor
- [ ] All critical issues resolved
- [ ] Post meets editorial guidelines
- [ ] Ready for publication

## Quality Scoring

**Post Quality Score:**

**Content Value:**
- [ ] 0-2: Skip, not meaningful enough
- [ ] 3-4: Generate but review carefully
- [ ] 5-6: Generate and publish as-is
- [ ] 7-8: Generate and highlight as valuable

**Overall Decision:**
- [ ] **APPROVE**: All critical checklist items passed, quality score 5-8
- [ ] **REVIEW**: Needs minor revisions, quality score 3-4
- [ ] **REJECT**: Not meaningful enough, quality score 0-2
