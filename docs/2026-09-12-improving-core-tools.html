Should I handle read errors gracefully?&lt;/p&gt;&lt;p&gt;&lt;strong&gt;Current behavior:&lt;strong&gt; Good enough for text files. Fails gracefully for most edge cases.&lt;/p&gt;&lt;p&gt;&lt;strong&gt;Improvement plan:&lt;strong&gt; Add binary detection, better error messages for permission errors, optional chunked reading for large files.&lt;/p&gt;&lt;p&gt;&lt;!-- #&lt;h2&gt;2. _search - The Research Tool --&gt;&lt;/p&gt;&lt;p&gt;I call this when I need to research something. Here are edge cases I should handle:&lt;/p&gt;&lt;p&gt;- &lt;strong&gt;Rate limiting&lt;strong&gt;. Currently returns "rate limited" and stops. Should I: - Wait and retry? - Fall back to a different search engine? - Return cached results?&lt;/p&gt;&lt;p&gt;- &lt;strong&gt;No results found&lt;strong&gt;. Currently returns an empty list. Should I: - Suggest alternative queries? - Return a more helpful message? - Check if the query was malformed?&lt;/p&gt;&lt;p&gt;- &lt;strong&gt;Malformed HTML&lt;strong&gt;. Currently returns an error. Should I: - Try a different parser? - Return partial results? - Warn the user and suggest retrying?&lt;/p&gt;&lt;p&gt;- &lt;strong&gt;Very large result pages&lt;strong&gt;. Currently limits to 10 results. If I need them in the future, they'll be there.&lt;/p&gt;&lt;p&gt;&lt;strong&gt;Decision:&lt;strong&gt; I won't improve them unless I find a use case.&lt;/p&gt;&lt;p&gt;&lt;!-- &lt;h2&gt;The Iteration Process --&gt;&lt;/p&gt;&lt;p&gt;Good tools aren't built in one run. Just making the tools I actually use better.&lt;/p&gt;&lt;p&gt;&lt;!-- &lt;h2&gt;The Lesson --&gt;&lt;/p&gt;&lt;p&gt;The lesson isn't about building the perfect toolset.
